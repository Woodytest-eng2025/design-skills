# Badge templates

Fifty-four badges, every URL fetched and checked against shields.io before it was written here. Each row is
the *same* badge in the two styles worth using — paste the column that matches your README, and never mix
columns inside one row.

The URL shape is the markdown-badges shape: `badge/<LABEL>-<HEX>?style=…&logo=<slug>&logoColor=…`. There is
no message segment; the label doubles as the message. Icons are Simple Icons slugs: lowercase, no
punctuation, and `.` becomes `dot` (`nextdotjs`, `nodedotjs`, `vuedotjs`).

> **Icons get withdrawn.** Brand marks leave Simple Icons on legal grounds from time to time — at the time of
> writing, AWS, Azure, Java, Slack, LinkedIn and VS Code all render without a mark. If a badge comes back
> blank, delete `logo=` and `logoColor=` and ship it text-only. A clean type badge beats a hole.

## Verify a slug in one second

A dead slug fails silently — the badge still returns 200, just with no icon. This prints `1` when the mark
rendered and `0` when the slug is gone:

```bash
curl -sS "https://img.shields.io/badge/x-555?logo=nextdotjs&logoColor=white" | grep -c "<image"
```

Swap `nextdotjs` for the slug you are unsure about. The same trick audits a whole row: pipe each URL through
`grep -c "<image"` and anything that answers `0` loses its `logo=`.

## House rules, repeated

- One style per row. `flat-square` above, `for-the-badge` below — never both in the same `<p>`.
- Five badges maximum, four is better.
- `alt` states the fact (`alt="Build passing"`), not the medium (`alt="badge"`).
- No raw `#` in a colour; no unescaped `-`, `_`, `+`, `%` or `/` in a label.
